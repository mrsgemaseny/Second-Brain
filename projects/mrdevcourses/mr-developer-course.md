# Mr Developer Course & Платформа Вайбкодинга

## Позиционирование и Философия Преподавания
> *"MrDeveloper — мой личный бренд. Его нужно предоставлять людям, рекламировать и продвигать. Идеи есть, проблемы очевидны, решения имеются → Можно войти в рынок без проблем."*

- **Стиль преподавания:** Не глубокая абстрактная теория, а базовая постройка систем и строгое соблюдение архитектуры.
- **Принцип «Без лишней теории»:** Теория даётся исключительно там, где она предотвращает конкретную инженерную ошибку (например: почему React Query, а не хаотичный useState; почему состояние должно быть на бэкенде, а не локально). Именно эта формулировка вынесена на лендинг.
- **Цель основного курса:** Научить мыслить архитектурно правильно и передать реальный боевой опыт через непрерывную практику.
- **Эволюция программ:** Глубокий курс появится тогда, когда основатель сам сможет читать и легко разбирать любые низкоуровневые решения. Текущий уровень (+-) осознаётся абсолютно нормально: есть прочное теоретическое и прикладное понимание, а глубина senior-инженера 5–7 лет нарабатывается практикой.

## Учебный План Флагманского Курса (5 недель × 6 уроков = 30 уроков)

### Неделя 1 — Введение и инструментарий
- **1.1**: Вайбкодинг как методология: сравнение с классической разработкой, место AI-ассистентов в современном IT-рынке.
- **1.2**: Настройка рабочего окружения: VS Code, Cursor, Antigravity, Claude, ChatGPT, Gemini — установка и верификация.
- **1.3**: Git и GitHub с нуля: инициализация репозитория, первый коммит, GitHub Pages — деплой статики.
- **1.4**: Структура проекта и MVP-мышление: файловая архитектура, README, `agents.md`.
- **1.5**: Бизнес-идея: Customer Problem Statement, целевая аудитория, feature scope.
- **1.6**: Лендинг бизнес-идеи: вёрстка через AI-ассистента, публикация на GitHub Pages.

### Неделя 2 — Frontend-разработка (Маркетплейс)
- **2.1**: Feature-Sliced Design: слои, сегменты, публичное API модуля — проектирование маркетплейса.
- **2.2**: Старт проекта: роутинг, страницы, базовая бизнес-логика.
- **2.3**: Углубление логики: ролевая модель (покупатель / продавец), условный рендеринг по роли.
- **2.4**: Деплой на GitHub Pages: конфигурация base path, сборка и публикация.
- **2.5**: Code review через Claude: рефакторинг, исправление архитектурных нарушений, дизайн-аудит.
- **2.6**: Финал маркетплейса: приёмочное тестирование, ретроспектива.

### Неделя 3 — Full-Stack + 3D (Трекер денег)
- **3.1**: Системная архитектура: монолит vs микросервисы, выбор стека, ERD базы данных — проектирование трекера.
- **3.2**: Инициализация full-stack: настройка фронтенда, бэкенда и БД, связка окружений.
- **3.3**: Закладка архитектуры: RBAC, JWT-аутентификация, защищённые роуты, миграции схемы.
- **3.4**: OAuth 2.0 через Google: интеграция провайдера, мультиаккаунтность, проверка ролей в админ-панели.
- **3.5**: Three.js — 3D-сцена, анимации, интерактив; Second Brain разработчика: Notion/Obsidian система.
- **3.6**: Code review: масштабируемость архитектуры, рефакторинг, финальный деплой Render + Vercel.

### Неделя 4 — CRM: Kanban + Trackers
- **4.1**: Полное планирование продукта: user stories, архитектурное решение, выбор стека с обоснованием.
- **4.2**: Технический foundation: README по стандарту, углублённый Second Brain, финализация tech stack.
- **4.3**: Самостоятельная работа студента: декомпозиция на фазы, написание промптов, старт реализации.
- **4.4**: Telegram Bot: webhook-интеграция, алерты, уведомления о событиях CRM.
- **4.5**: Code review + CI/CD pipeline: GitHub Actions, деплой на Vercel (фронт) и Render (бэк).
- **4.6**: Production-режим: smoke testing, мониторинг, работа с живыми данными.

### Неделя 5 — Pensee (всё в одном)
- **5.1**: Архитектура финального продукта: scope, интеграционная карта всех компонентов — старт.
- **5.2**: Подключение LLM API: Claude / OpenAI, prompt engineering, обработка ошибок и контроль токенов.
- **5.3**: AI-ассистент: chat-интерфейс, контекстное окно, streaming-ответы.
- **5.4**: RAG-система и AI Core: Groq API, реактивный WebClient, Server-Sent Events (SSE), детерминированное закрытие подписок, PII-маскирование.
- **5.5**: Google SMTP / Gmail API: отправка транзакционных писем из приложения — подготовка к релизу.
- **5.6**: Финал Pensee: полный деплой, нагрузочное тестирование, презентация продукта.

## Технический Аудит Платформы MrDevCourses (Formal, Сентябрь 2026)
- **Версия и статус:** `v1.0.0-PROD`, Pre-Release Pilot, **Level 3 — Strong Educational MVP** (оценка 8.5/10).
- **Стек:** Spring Boot 3.3.0 + React 19 + TypeScript 5.7 + Vite 6.1 + Tailwind v4 + PostgreSQL 17 + Telegram Bot API + Bucket4j + Caffeine L1.
- **БД и Кодовая база:** 23 JPA-сущности, 67 Flyway-миграций, 56 REST-эндпоинтов в 25 контроллерах.
- **Тестовое покрытие:** 250 backend-тестов (JUnit 5) + 80 frontend-тестов (Vitest, 33 сьюта) — 100% GREEN, 0 ошибок сборки.
- **Архитектурные фичи:**
  - *Drip-content без Cron:* вычисление доступности урока на лету через чистый SQL.
  - *Anti-Cheat Quiz:* поле `isCorrect` зануляется перед сериализацией в DTO, проверка строго на сервере.
  - *Неизменяемый аудит:* DB-триггер `BEFORE UPDATE OR DELETE` на таблице `audit_logs` блокирует любые изменения даже суперюзером.
  - *SOS Help Request:* накопление датасета (код студента + ответ ментора) для обучения будущего RAG.
  - *Native Fetch Interceptor:* zero-dependency HTTP клиент с X-Request-ID без Axios.
  - *Cookie Guard:* httpOnly JWT cookie (`MrDev_token`) вместо небезопасного localStorage.
